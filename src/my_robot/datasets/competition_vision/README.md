# 场景检测数据

运行 `python3 build_dataset.py` 可从项目素材重建检测数据。提交的图像、标签和配置已生成；`person.yaml` 与 `plate.yaml` 均可交给 Ultralytics 的训练或验证入口。每行标签采用 `类别 x中心 y中心 宽 高` 的归一化检测框格式，类别编号均为 0。

| 任务 | 训练来源 | 验证来源 | 每组图像 | 每图目标数 |
| --- | --- | --- | ---: | ---: |
| 人偶 | A 立牌原图 | B 立牌原图 | 3 | 训练 4、验证 5 |
| 车牌 | 场景车辆原图 | Gazebo 停车相机画面 | 3 | 训练 1、验证 2 |

每个来源保存原图、暗光和强光三个亮度版本；亮度变化不改动框坐标。按原始素材分组后再划分训练与验证，避免同一张基础图的亮度版本跨组。Gazebo 验证帧来自项目 2026-10-08 的停车相机记录，原帧保存在 `sources/plate_stop_camera.png`。三辆车的场景贴图相同，车牌验证集只检查这张牌在仿真画面中的检测，不用于评估不同号码的泛化。人物验证集只含 B 立牌，不能代表真实行人分布。框坐标由原图人工检查，若替换素材，需要重新核对标签。

加载 ROS 和项目虚拟环境后，可运行 `python3 train.py person` 或 `python3 train.py plate` 进行微调。轮数、尺寸与批量在 `training.yaml`；新权重写入工作区的 `log/training`，不会覆盖 `models` 下的运行权重。运行前先用 `python3 validate_dataset.py` 检查图像与标签。`python3 evaluate.py` 会用现有运行权重验证两套数据，并更新 `validation_results.json`。该文件同时记录权重哈希、验证图像数和检测框数，便于与报告数字核对。
